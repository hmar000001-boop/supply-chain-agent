# M4 mechanism traceability — S/C/T/P/F/L/R

This table records the actual M4 realization boundaries. It is not a claim that every engineering choice below is specified by the source paper.

| Bundle | S — State | C — Control | T — Trigger | P — Persistence | F — Failure | L — Learning | R — Resources |
|---|---|---|---|---|---|---|---|
| **B1** | Typed candidates bridged from all four M2 memory types; scope, lifecycle/knowledge-time, access history, cue associations, downstream-utility estimate, context units, measured I/O latency and maintenance profile. | `B1RetrievalSelector` owns ranking/admission under a scoring policy; M2 remains the source of retrieved records; feature provider is trusted. | A retrieval result is converted to candidates and a `B1SelectionRequest` supplies cues, time, budget and policy. | Access history and maintenance events are supplied/recorded through ports; current maintenance ledger is in-memory; selection result is ephemeral. | Cross-scope candidates, expired working memory, not-yet-verified episodes, inactive facts/procedures, duplicate IDs and invalid scores are rejected. | Actual maintenance events are accounted idempotently. No automatic activation-model training or downstream utility calibration is implemented. | Context-unit budget, maximum candidate count, cognitive-latency penalty, I/O-latency penalty and maintenance horizon/cost. Cognitive and infrastructure latency remain separate. |
| **B2** | Typed impasse signal, parent scope/request/version/objective fingerprint, child capabilities, deadline, action budget, child findings/assumptions/disposition. | Parent owns objective and final action; child receives a strict read/reasoning allow-list bounded by parent grant. `ImpasseResolutionService` controls case lifecycle. | Validators emit typed signals; detector consolidates by type/subject and severity. | Case repository is in-memory in M4; terminal result/reason retained in the case. M7 provides durable records. | Parent drift, scope or fingerprint mismatch, unauthorized child capability, action-budget exhaustion, expiry and unresolved child result cause rejection/escalation. | Findings are returned for parent verification; no automatic procedure learning or parent mutation occurs. New attempts use a new case identity. | Wall-clock deadline and maximum child action count; child capabilities restricted to read/reasoning. |
| **B3** | Candidate envelope with kind, scope, utility, reliability, risk, context units, coverage tags, conflicts, mandatory flag and evidence; immutable snapshot, coverage, coalition and consumer receipts. | Admission policy protects mandatory content, evaluates optional content and checks conflicts symmetrically. Consumers receive only admitted snapshot content. | A cycle creates an admission request; after admission, an explicit broadcast call selects consumers. | Workspace repository is in-memory. Broadcast receipts are synchronous and returned to caller; durable outbox/replay is M7. | Mandatory capacity/count failure yields no partial snapshot; scope mismatch, conflicts, incomplete coverage, malformed receipts, closed snapshot broadcast and consumer failures are represented/rejected. | Consumer receipts provide outcome signals, but no automatic scoring-policy update is implemented. | Context capacity, maximum candidate count, optional candidate score and marginal coverage value. |
| **B4** | Recovery intention with scope, objective ID/fingerprint/owner, protected constraints, current method, status/version, suspension return state, delegation ID and completion proof. | Explicit transition methods; method change requires reconsideration and unchanged fingerprint. Parent objective cannot be changed by delegation result. | Active objective creates intention; new evidence/impasse requests reconsideration; interruption suspends; bounded investigation delegates/returns; proof completes. | Compare-and-set in-memory intention repository; durable PostgreSQL and audit history are M7. | Stale version, illegal transition, objective fingerprint mismatch, invalid proof time, wrong delegation ID and time regression are rejected. | Verified completion and typed delegation return inform the current intention. No autonomous code/procedure mutation or automatic policy learning. | Lifecycle time and bounded delegation are represented; computational budget remains B6 and business resources remain domain-owned. |
| **B6** | Three required uncertainty dimensions; per-execution budget limits, consumed and reserved amounts, deadline and next-step declared resource requirements. | `MetaControlGovernor` chooses continue, request evidence, reduce computation, interrupt for human/budget replenishment or stop. Budget ledger atomically reserves/commits/releases in-process. | Evaluated at a decision boundary before a next step; deadline, actual overrun and uncertainty thresholds trigger control. | Resource ledger is in-memory in M4; durable accounting and authorized replenishment are M7. | Missing uncertainty dimension rejected; hard deadline/actual overrun stops; insufficient next-step budget interrupts; arithmetic saturates to avoid overflow masking an overrun. | Usage is recorded. Adaptive threshold learning or automatic budget-policy training is not implemented. | Model calls, input/output tokens, reasoning evaluations, search expansions, MCTS rollouts, external reads and verification calls. Inventory, money and supplier capacity are explicitly not computational units. |

## Bundle boundary

- **B5/GraSP:** not implemented as a residual mechanism in this codebase. It remains the reviewed closed-candidate/comparison boundary.
- **CoT/ToT/MCTS:** not implemented by M4; independent algorithms are M5.
- **LangGraph4j:** not used in this module; M6 composes these capabilities into the outer graph.
- **Durable database adapters:** not implemented in M4; M7.

## Source-level mapping

- B1: `mechanisms.b1` — `B1MemoryCandidateFactory`, activation estimator, cognitive latency model, `B1RetrievalSelector`, maintenance ledger/accounting.
- B2: `mechanisms.b2` — typed detector/signals, `ImpasseResolutionCase`, child result, service and repository port.
- B3: `mechanisms.b3` — candidate/scoring/admission, immutable snapshot, explicit coalition, broadcast, consumer receipt and repository port.
- B4: `mechanisms.b4` — objective fingerprint, `RecoveryIntention`, lifecycle service and repository port.
- B6: `mechanisms.b6` — uncertainty assessment, resource budget/reservation ledger, governor, decisions and resume conditions.
